📖 How this simulation works — exactly ▼
Starting point
You write a plain description of a system. CySyMo extracts assets, vulnerabilities, threats, an impact matrix A_I and probabilities p. Risk is R = (Σ e_i · A_Iij · p_j) / (m·n). The simulation runs two Claude agents on this real data. Nothing is invented.
🔴 Stage 1 — Reconnaissance
Claude receives:
→ Asset names only — no vulnerabilities visible yet
→ Message: "You are outside. You cannot see vulnerabilities yet."
→ Budget: 100 pts

Claude chooses one of:
→ scan_network — active, finds ALL vulns (5 pts, detectable)
→ passive_recon — stealthy, finds 60% of vulns (5 pts)
→ fingerprint_services — probes one asset (5 pts)

After: vulnerabilities and their e_i values are now known to the attacker. Stage → Initial Access.
🔴 Stage 2 — Initial Access
Claude receives:
→ Full list of open vulnerabilities with e_i values and NIST controls
→ Asset list with IDs
→ Budget remaining

Claude chooses one of:
→ exploit_vuln V3 — targets a specific vuln (15 pts, success ∝ e_i)
→ phishing — social engineering (12 pts)
→ brute_force — credential attack (10 pts, noisy)

Strategy: Claude picks the vuln with highest e_i — weakest NIST control = easiest to exploit.
🔴 Stages 3 → 6
Stage 3 — Persistence:
Claude knows its foothold. Choices: install_backdoor, create_account, scheduled_task.

Stage 4 — Lateral Movement:
Claude sees controlled vs unreached assets. Choices: lateral_movement, pass_the_hash, pivot.

Stage 5 — Privilege Escalation:
Choices: privilege_escalation, kernel_exploit, sudo_abuse.

Stage 6 — Exfiltration:
Choices: exfiltrate_data, covert_channel, compress_encrypt.
Success = Attacker wins.
🔵 Defender — What Claude always knows
The defender knows its own system from turn 1:
→ All vulnerabilities + NIST controls + effectiveness
→ e_i = 1 − effectiveness for each vuln
→ Budget, IDS level, MFA, segmentation status

The defender does NOT know:
→ Where the attacker is
→ What the attacker scanned
→ The attacker's next action

It learns about the attacker only through IDS alerts — and only when the attacker is detected (probability depends on IDS level).
🔵 Defender — Choices and R impact
Claude chooses one action per turn:
→ patch_vuln V3 (20 pts) → R decreases — e_i→0, vuln removed from Σ
→ enable_mfa (10 pts) → R decreases — effectiveness↑, e_i↓ for all vulns
→ deploy_ids (25 pts) → detection %↑ — R unchanged
→ network_segmentation (30 pts) → blocks lateral — R unchanged
→ incident_response (20 pts) → evicts attacker — R unchanged
→ honeypot (15 pts) → wastes attacker turn — R unchanged

Strategy: patch the vuln with highest e_i first.
📊 Does R always go to zero?
R = (Σ e_i · A_Iij · p_j) / (m·n)
No. R only drops when e_i drops — i.e. when a vuln is patched or effectiveness rises.

Reconnaissance, persistence, lateral movement, and backdoors do not change R — they change the attacker's position, not the formula values.

On a weak system (high e, high A_I), R stays high if the attacker moves faster than the defender patches. The R(t) chart below shows you exactly when and why R changes.
